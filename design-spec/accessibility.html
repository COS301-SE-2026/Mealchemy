07 Accessibility

Accessibility Guidelines

Mealchemy targets WCAG 2.2 Level AA with readable text, visible labels, accessible touch targets, and consistent focus and error states.

TargetWCAG 2.2 AA

AA is the minimum conformance target across colour, navigation, forms, and feedback.

FocusVisible ring

Keyboard focus uses a 3px gold outline on links, buttons, and inputs.

MotionReduced motion

Motion is reduced when the user's device requests fewer animations.

ContrastAA pairings

Approved foreground/background pairs are documented and checked below.

WCAG 2.2 Level AA Adherence

These are the WCAG standards Mealchemy is aiming to meet, with the design guideline we will follow for each one.

1.4.3

Minimum Contrast: Text

WCAG Standard

Normal text requires 4.5:1 contrast. Large text requires 3:1.

Mealchemy Guideline

Use only approved text/background pairings from the contrast table. Muted text is reserved for non-actionable supporting copy on light backgrounds.

1.4.11

Non-Text Contrast

WCAG Standard

Meaningful icons, focus indicators, and interactive component boundaries require 3:1 contrast against adjacent colours.

Mealchemy Guideline

Buttons, icons, focused input borders, and semantic states must use contrast-safe maroon, gold, or semantic colours. Decorative dividers must not be the only source of meaning.

1.4.1

Use of Colour

WCAG Standard

Colour must not be the only way information is communicated.

Mealchemy Guideline

Pair every colour state with text, a number, or an icon. Pantry status, form validation, and match badges must all remain understandable without colour alone.

2.5.5

Target Size

WCAG Standard

Interactive targets should be at least 44x44 CSS pixels.

Mealchemy Guideline

Keep medium buttons at 48dp, large buttons at 56dp, and icon buttons at 48dp unless a specific layout needs a larger value.

1.3.1

Info and Relationships

WCAG Standard

Visual structure and relationships must also be available programmatically.

Mealchemy Guideline

Use accessible labels for meaningful controls and status information. Exclude decorative imagery from the accessibility tree.

1.3.5

Identify Input Purpose

WCAG Standard

Inputs should programmatically identify their purpose so assistive tools can present the right keyboard or autofill support.

Mealchemy Guideline

Give every form field a visible label, plus the correct input type and autofill support where relevant.

1.4.4

Resize Text

WCAG Standard

Text must remain readable and functional up to 200% scaling without loss of content or functionality.

Mealchemy Guideline

Use flexible layouts that respect device text scaling. Test at 1.0x, 1.3x, and 2.0x before release.

2.1.1

Keyboard

WCAG Standard

All functionality must be operable with a keyboard, with no keyboard traps.

Mealchemy Guideline

Ensure every action is keyboard reachable on tablet and desktop layouts, with visible focus feedback on fields, buttons, and navigation items.

3.3.1

Error Identification

WCAG Standard

Detected errors must be identified and described in text.

Mealchemy Guideline

Use specific written error messages, such as "Incorrect password. Try again.", instead of generic error labels.

3.3.2

Labels or Instructions

WCAG Standard

Form fields must include labels or instructions.

Mealchemy Guideline

Avoid placeholder-only fields. Use persistent visible labels so input purpose remains clear before and after typing.
