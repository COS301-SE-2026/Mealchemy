07 Accessibility

Accessibility Guidelines

Mealchemy targets WCAG 2.2 Level AA with readable text, visible labels, accessible touch targets, and clear focus states.

Colour Independence

Colour-coded states always include visible text labels, such as Fresh, Low, Expired, or a form error message.

Touch Targets

Interactive elements meet the 48x48dp Material target where possible; icon buttons are 44x44dp.

Dynamic Text

Layouts support system text scaling and are checked at 1.0x and 1.3x scale.

Keyboard Focus

Interactive elements are reachable by keyboard and use a 3px primary-colour focus ring.

WCAG 2.2 Level AA Adherence

These are the WCAG standards Mealchemy is aiming to meet, with the design guideline we will follow for each one.

1.4.3

Minimum Contrast: Text

WCAG Standard

Normal text requires 4.5:1 contrast. Large text requires 3:1.

Mealchemy Guideline

Use only approved text/background pairings from the contrast table. Muted text is reserved for non-actionable supporting copy on light backgrounds.

1.4.11

Non-Text Contrast

WCAG Standard

Meaningful icons, focus indicators, and interactive component boundaries require 3:1 contrast against adjacent colours.

Mealchemy Guideline

Buttons, icons, focus rings, and input borders must use contrast-safe maroon, gold, or semantic colours. Decorative dividers must not be the only source of meaning.

1.4.1

Use of Colour

WCAG Standard

Colour must not be the only way information is communicated.

Mealchemy Guideline

Pair every colour state with text, a number, or an icon. Pantry status, form validation, and match badges must all remain understandable without colour alone.

2.5.5

Target Size

WCAG Standard

Interactive targets should be at least 44x44 CSS pixels.

Mealchemy Guideline

Keep primary buttons at 48dp, bottom navigation at 64dp, and icon buttons at no less than 44dp.

1.3.1

Info and Relationships

WCAG Standard

Visual structure and relationships must also be available programmatically.

Mealchemy Guideline

Use Flutter Semantics labels for meaningful controls and status information. Exclude decorative imagery from the accessibility tree.

1.3.5

Identify Input Purpose

WCAG Standard

Inputs should programmatically identify their purpose so assistive tools can present the right keyboard or autofill support.

Mealchemy Guideline

Give every form field a visible label, plus the correct Flutter keyboardType and autofillHints where relevant.

1.4.4

Resize Text

WCAG Standard

Text must remain readable and functional up to 200% scaling without loss of content or functionality.

Mealchemy Guideline

Use flexible layouts that respect Flutter text scaling. Test at 1.0x, 1.3x, and 2.0x before release.

2.1.1

Keyboard

WCAG Standard

All functionality must be operable with a keyboard, with no keyboard traps.

Mealchemy Guideline

Ensure every action is keyboard reachable on tablet and desktop layouts, with a visible 3px primary-colour focus ring.

3.3.1

Error Identification

WCAG Standard

Detected errors must be identified and described in text.

Mealchemy Guideline

Use specific written error messages, such as "Incorrect password. Try again.", instead of generic error labels.

3.3.2

Labels or Instructions

WCAG Standard

Form fields must include labels or instructions.

Mealchemy Guideline

Avoid placeholder-only fields. Use persistent visible labels so input purpose remains clear before and after typing.

Colour Independence Examples

State is communicated with both colour and text, so users do not need to rely on colour alone.

Fresh

Green dot plus label for usable pantry items.

Low

Orange dot plus label for low-stock ingredients.

Expired

Red dot plus label for expired pantry items.

Form validation

! Incorrect password. Try again.

Testing Approach

Accessibility will be checked using Flutter accessibility testing, semantic label review, keyboard navigation checks, contrast-ratio checks, and Lighthouse accessibility testing in the browser. These tests support the WCAG 2.2 Level AA guidelines listed above.
